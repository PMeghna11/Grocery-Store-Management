# Grocery Store Management System using SQL

## Project Overview
The Grocery Store Management System is a SQL-based project designed to organize grocery store data and analyze business performance using a relational database. It manages information about customers, products, suppliers, employees, categories, and orders across seven interconnected tables.

The project uses SQL queries to analyze customer purchasing behavior, product performance, sales trends, supplier contributions, and employee activity. The insights support better business decision-making and operational efficiency.

## Business Problem
Grocery stores manage large volumes of data related to products, customers, suppliers, employees, and orders. Manual data management can lead to errors, duplicated records, and difficulties tracking sales and customer behavior. This project addresses these challenges by organizing data in a relational database and using SQL to extract meaningful business insights.

## Project Objectives
- Design a relational database for grocery store operations.
- Manage customer, product, supplier, employee, category, and order data.
- Identify unique customers and top customers by purchase amount.
- Analyze product sales volume and revenue.
- Examine monthly order and revenue trends.
- Identify suppliers providing the most products.
- Analyze employee order-handling activity.
- Calculate the average order value and average quantity ordered per product.

## Technologies Used
- **Database:** MySQL
- **Language:** SQL
- **Concepts:** Joins, aggregate functions, GROUP BY, ORDER BY, filtering, subqueries, primary keys, and foreign keys

## Database Schema
The database contains seven tables:

| Table | Description |
|---|---|
| `supplier` | Stores supplier details |
| `categories` | Stores product category information |
| `employees` | Stores employee details |
| `customers` | Stores customer information |
| `products` | Stores product names, prices, supplier IDs, and category IDs |
| `orders` | Stores order information, customer IDs, employee IDs, and order dates |
| `order_details` | Stores products ordered, quantities, unit prices, and total prices |

### Table Relationships
- One supplier can supply multiple products.
- One category can contain multiple products.
- One customer can place multiple orders.
- One employee can process multiple orders.
- One order can contain multiple order-detail records.
- One product can appear in multiple order-detail records.

Primary and foreign keys connect the tables and help maintain referential integrity.

## Business Questions and SQL Analysis
The project addresses the following business questions:

1. How many unique customers have placed orders?
2. Who are the top five customers by total purchase amount?
3. Which products have the highest total sales volume by quantity?
4. What is the total revenue generated by each product?
5. What are the monthly trends in order volume and revenue?
6. Which supplier provides the most products?
7. Which employees have handled the most orders?
8. What is the average value per order?

Additional analysis can include average quantity ordered per product and product sales by category and supplier.

## SQL Concepts Demonstrated
- **JOIN:** Combines data from related tables.
- **COUNT() and COUNT(DISTINCT):** Counts orders, records, and unique customers.
- **SUM():** Calculates quantities and revenue.
- **AVG():** Calculates average prices, quantities, and order values.
- **GROUP BY:** Summarizes data by customer, product, supplier, employee, or month.
- **ORDER BY and LIMIT:** Ranks results and retrieves top-performing records.
- **Date functions:** Supports analysis of order patterns over time.
